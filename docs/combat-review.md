# Проверка боевой логики

Ветка: `fix/combat-code-review`.

## Изменения

- РЭБ подавляет захват/стрельбу на 3 секунды игрового времени, сохраняя выбранную цель. Повторное воздействие продлевает подавление. Приостановка времени приостанавливает эффект. Движение EnemyAI продолжается.
- При активном EnemyAI только он выдаёт команды движения; ShipWeapon управляет манёврами кораблей без активного EnemyAI.
- Форсаж — отдельный множитель скорости и тяги. Смена оборудования обновляет базовые характеристики независимо от форсажа. Отключение компонента очищает усиление.
- Мгновенный выстрел учитывает вероятность попадания: Clamp01(точность атакующего − уклонение цели). Отдельная проверка на каждый ствол; промах тоже показывает след выстрела. В последующей реализации типов оружия все выстрелы переведены на общий мгновенный расчёт; см. combat-features.md.
- Клики по окну оснащения, кнопке его открытия, тактической панели и Canvas UI не выдают приказ движения и не вызывают ручной выстрел. Автоматический огонь по захваченной цели продолжается. Мышь больше не инициирует ручной огонь у врага.

## Локальная проверка в Unity 6000.5.7f1

Эти сценарии подготовлены, но в облаке не выполнялись: редактор отсутствует. `git diff --check` проверяет только оформление diff, а не компиляцию.

1. Дождаться импорта и компиляции; убедиться, что Console не содержит ошибок. Открыть CombatSandbox.
2. Назначить противнику рабочее оружие, захватить его. Применить РЭБ: три секунды игрового времени он не стреляет; затем возобновляет огонь по прежней цели в пределах сектора/дальности. Проверить паузу и скорость 2x. На цели без ShipWeapon способность не должна тратить перезарядку.
3. У врага с EnemyAI проверить следование и орбиту. Отключить EnemyAI: ShipWeapon должен подхватить маневрирование. Повторно включить AI: команды снова выдаёт только AI.
4. Включить форсаж, установить/снять двигатель во время его действия. Скорость и тяга должны быть удвоены относительно нового оснащения; через две секунды должны остаться новые базовые значения. Отключение/включение ShipAbilities не должно оставлять усиление навсегда.
5. Для проверки попаданий временно установить accuracy=1 и baseEvasion=speedEvasionMultiplier=0: попадания гарантированы. При accuracy=0 попаданий нет. Для обычных значений собрать достаточную выборку; не проверять вероятность по одному выстрелу. Восстановить исходные значения после проверки.
6. Нажать кнопки тактики и способностей, открыть/закрыть фитинг, перетащить предметы, нажать Canvas-кнопку: маршрут не меняется. Клик по миру по-прежнему задаёт маршрут, клик по врагу — цель. Без цели удержание мыши игрока не должно заставлять врага стрелять.

## Предложения по новым возможностям

1. **Журнал боя и индикация эффектов.** Показывать попадания, промахи, повреждения модулей и оставшееся время РЭБ/форсажа. Это сделает новую вероятность попаданий понятной игроку.
2. **Профили оснащения.** ScriptableObject для описаний предметов, сохранение комплектов по ID и восстановление между боями. Сейчас каталог создаётся прямо в ShipFitting и всё оснащение теряется при перезапуске сцены.
3. **Ремонт и восстановление щита.** Отдельные правила регенерации после задержки и ремонта выбитых модулей; стоимость и ограничения, чтобы не получить бесконечное лечение в бою.
4. **Единый тактический контроллер.** Вынести движение из ShipWeapon, дать игроку и AI общий набор приказов. Текущее исправление убирает конкуренцию двух компонентов, но разделение ответственности упростит добавление новых манёвров.
5. **Воспроизводимые бои и автотесты.** Выделить расчёт попаданий/урона в независимую модель с управляемым генератором случайных чисел, добавить тесты щитов, модулей, эффектов и смены оснащения.

Часть предложений теперь реализована в этой ветке. Актуальные механики и ограничения описаны в [combat-features.md](combat-features.md).
